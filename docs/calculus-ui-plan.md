# Calculus and TI template expansion

Status: implementation in progress.

The goal is native calculus walkthroughs integrated with TI expression templates and a responsive calculator interface. TI CAS parity is the longer-term target. Completion of this plan establishes the supported families below and does not establish complete CAS parity.

## Decisions

- Use the existing Giac C++ backend for symbolic evaluation and independent comparisons. Reuse the existing GMP arithmetic. Select established libraries by technical fit, target support, maintenance, memory use and package cost. License choice does not constrain this work. Retain required notices.
- Native steps must explain actual mathematical transformations with checked preconditions. A CAS answer alone is not a walkthrough.
- Preserve the existing working-tree changes. Implementation scope includes calculus, command dispatch, the Lua bridge, the Giac adapter, capability registration, the UI and their tests and build registration.
- This file is the authorized planning document. Other documentation remains unchanged unless its update is authorized.
- Use the native TI editor for mathematical entry and typesetting. Keep keypad navigation, readable fallback text and full-expression access.
- Make substantial use of nGC and nRGBlib where verified compatible with the resident UI. Inspect both SlyVTT Widget libraries for reusable toolkit ideas and avoid unsupported framebuffer assumptions.
- Integrate ETL alongside the STL in bounded structures where allocation counts, memory use or latency improve. Keep capacity exhaustion explicit and preserve existing ownership contracts.
- Also integrate EASTL where measured container behavior improves the application. Pin its EABase dependency and verify allocation hooks, exception settings and target ABI before use.
- Build the expanded interface around retained objects, layout and rendering. Use LVGL for advanced controls, flex and grid layout, scrolling and focus. Qualify its bounded memory use and TI image presentation before enabling product surfaces.
- Preserve antialiased native TI text and equation rendering. Composite native symbol coverage in linear light. Important answers and conditions must remain fully reachable through wrapping and scrolling.
- Use RAII for owned resources and standard smart pointers for heap ownership. Prefer unique ownership, and use shared ownership only when the lifetime requires it. Borrowed views must not outlive their owner. Resident storage must also remain safe when Ndl unloads a module without C++ finalization.
- Keep host, emulator and physical-device evidence separate. Production quality requires runtime evidence and cannot be inferred from compilation.

## Additional solver references

The elementary limit extension follows the hypotheses of [OpenStax L'Hopital's rule](https://openstax.org/books/calculus-volume-1/pages/4-8-lhopitals-rule). Native admission proves smoothness near the finite rational point and exact derivative values through the polynomial denominator's vanishing order. Nonzero polynomial derivatives have isolated roots. Repeated reduction stops at a continuous quotient with a nonzero denominator. This reuses the existing native derivative recorder and Giac comparison rather than adding another symbolic runtime.

The affine logarithm family follows the integration-by-parts identity in [Rubi logarithm rules](https://github.com/RuleBasedIntegration/Rubi/blob/master/Rubi/IntegrationRules/3%20Logarithms/3.1.1%20(a%2Bb%20log(c%20x%5En))%5Ep.m) and the constant-coefficient substitution in [Rubi affine logarithm rules](https://github.com/RuleBasedIntegration/Rubi/blob/master/Rubi/IntegrationRules/3%20Logarithms/3.3%20u%20(a%2Bb%20log(c%20(d%2Be%20x)%5En))%5Ep.m). The native implementation uses the existing rule recorder, adds explicit real-domain restrictions, and asks Giac to verify the resulting identity. Rubi remains a rule reference, with no Mathematica runtime added.

These projects are candidates for reusable rule data, host tooling and implementation ideas. None has been added as a runtime dependency. Rubi and GeoGebra are the first comparison targets for the current calculus and walkthrough work. Direct adoption remains subject to target qualification, not license selection.
