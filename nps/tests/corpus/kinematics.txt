# One-dimensional constant-acceleration kinematics, PRD section 22.1 row 4.
#
# The required result is model choice, symbolic isolation, units and a final check. The first and
# the last are the engine's own: the plan records which equation was chosen and why the others were
# not, and the linear solver substitutes its candidate back. What a case pins is the problem, the
# answer with its unit, and the outcome.
#
# The symbolic isolation step is Giac's, and Giac is not linked on the host, so on this run that
# step records that no backend was given. The isolation itself is device evidence.
#
# The result is the value as reported with its unit, so a case whose givens are measured names the
# rounded value and a case whose givens are exact names the exact one.

# A unit that ends in an operator should not be a unit, and the scanner has the words for it: "a
# unit ends with nothing after its last operator". They are unreachable at the top level, because
# A unit ending in an operator is refused by the scanner. These two pinned the hole where it was not:
# "m/" used to read as "m", so 5 m/ was five metres and only the dimension check caught it, and
# "m/s^2*" used to read as "m/s^2" and solve as if nothing were wrong.
case kinematics.units.trailing-division
  family kinematics
  input find v; v0 = 5 m/; a = 3 m/s^2; t = 4 s
  expect not parsed

# Ten point zero less nine point nine nine is one hundredth, and the cancellation leaves one
# significant figure where all three givens had three. A rule that carried the fewest figures of the
# inputs would report 0.0100 and claim two figures the subtraction destroyed.

  family kinematics
  input find a; v = 10.0 m/s; v0 = 9.99 m/s; t = 1.00 s
  expect solved
  result 0.01 m/s^2

# Three figures, not the two the least precise given carries. I wrote 4.0 first, from the fewest
# significant figures among the givens, and that rule is only the one for products. The sum
# 5.0 + 17.0 follows decimal places instead, so 22.0 has three figures although 5.0 has two, and
# every step after it does too.
case kinematics.measured.time-from-three-measured-givens
  family kinematics
  input find t; x = 44.0 m; v0 = 5.0 m/s; v = 17.0 m/s
  expect solved
  result 4.00 s
