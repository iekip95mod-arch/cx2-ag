# Invalid, unsupported, resource-limit and adversarial inputs, PRD section 22.1 row 5.
#
# The required result is a correct non-success outcome with no fabricated continuation, which is MVP
# criterion 11. The audit enforces that on every case in this family and on no other: the outcome
# must not be a complete verified solution, and the engine must not hand back an answer. A case that
# also names a detail pins the words it was refused with, which is criterion 8's "fails clearly".
#
# A case names a mode because the input alone does not say which engine should have refused it.

# The answer is the signed minimum, which is representable, but reaching it takes the solver past
# what its exact integer arithmetic will do. Running out of room is not a claim that the equation
# was the wrong shape, so it is the resource outcome and the backend gate reads it as terminal.

# A divisor that is only zero once its like terms are gathered. Every one of these used to be
# answered rather than refused, and the integral ones came back as complete verified derivations
# carrying the condition "(y + (-y)) is not zero", which no value of y can meet. One case per engine
# the corpus can reach, because the guard that was missing was missing from four of the five.

# The square-root rule's refusals. Its envelope is rational perfect squares over the reals, so the
# two ways out of it are a square with no exact root and an equation with a term of degree one, and
# both have to leave nothing behind rather than reporting the nearest thing they can reach. A decimal
# root is the fabricated continuation criterion 11 is about: 5 has a square root and this rule may
# not name it.
case invalid.quadratic.square-with-no-exact-root
  family invalid
  mode quadratic
  input x^2 = 5
  unknown x
  expect outside the declared envelope
  detail the square of x is 5, whose square root is not exact, and this rule reports no decimals
